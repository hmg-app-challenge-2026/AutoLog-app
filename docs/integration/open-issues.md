# 프론트 ↔ 백엔드 — 미연결 · 불일치 · 정책 논의 목록

> 기준: 작성 2026-11-11 Frontend `8ca4ff0` · Backend `aedb43e`. **같은 날 두 리포를 AutoLog-app 하나로 합쳤다**(스펙 D-33) — 백엔드는 `ec91fcc`(운영 웹 장소·배차, QR 3초 확인, 메일 수정)까지 들어왔고 아래 항목에 영향 없음.

## 1. 연결되지 않은 것 (계약·구현이 없다)

### I-01 차량 id가 계약에 없다 (G-02 · R-10 요청함)
- **현상:** `PurposeEngine.orderedUsers(vehicleId)`·`suggest(TripFacts(vehicleId))`는 차량 id가 필요한데 화면이 받는 `DeviceApi`·`ConnectionState`에는 번호판 라벨만 있다. 프론트는 `"unregistered"`를 넘긴다(`RealAppGraph.vehicleId()`).
- **영향:** 배차 기반 운전자 순서·"배차" 배지(F-15), 배차 규칙 목적 추천(F-08 a)이 실제 앱에서 비어 있다.
- **제안:** `DeviceApi.vehicleId: StateFlow<String?>` — 요청서 [`requests/R-10-vehicle-id.md`](requests/R-10-vehicle-id.md). 받으면 프론트는 한 줄.
- **함께 정할 것:** 등록 전에 기록한 운행은 `vehicleId = "unregistered"`로 남아 등록 뒤 `unassignedTrips(진짜 id)`에서 빠진다 — 의도인가.

### I-02 사내 서버 업로드 계약이 없다 (G-04 · R-4)
- **현상:** 차 → 사내 서버 운행 사본 전송 계약·구현이 없다(core `UploadState`는 늘 null). 프론트 실제 앱은 `UnavailableUploadApi`.
- **영향:** 설정 › 회사 정보에 "전송 대기 0건 · 마지막 전송 없음 · [지금 전송]"이 보이고 누르면 "사내 서버 전송은 아직 준비 중이에요"로 실패. 운행 기록 줄의 전송 상태는 저절로 안 보인다. 운행기록부의 "사내 서버로도 자동 전송돼요"는 업로드가 켜져 있을 때만 보이게 막아 두었다.
- **정할 것:** ① R-4 일정 ② 그 전까지 회사 정보 섹션을 숨김 / "준비 중" 한 줄 / 그대로. 섹션 이름("회사 정보")과 내용(서버 전송 상태)이 맞는지도.

### I-04 계약이 없는 화면 기능 (G-08 · MVP 보류)
| 기능 | 백엔드 | 비고 |
|---|---|---|
| 운행 삭제 | 없음. 지워지는 길은 복구 팝업 [삭제]와 이동 없음 자동 버림뿐(`DISCARDED`, 실제 행은 남음) | 2026-11-11 사용자: MVP라 없어도 됨. 만든다면 `DISCARDED` 재사용 + 지울 수 있는 조건(확정 전만? 보낸 기록부에 든 운행은?)을 먼저 정해야 한다 — 세무 증빙 |
| 직원 지우기 | `SettingsApi`에 없음 | 설정 › 직원은 추가만 |
| 운행기록부 보관함(F-24) | Room `reports` 테이블은 있으나 조회 계약 없음 | 보낸 기록부 다시 보기 불가 |
| 거리 직접 입력 | 없음 | 계기판을 못 읽은 운행은 "거리 미확정"으로 엑셀까지 간다 |
| 비용 기록 삭제·수정 | 없음 | 잘못 넣은 주유는 고칠 수 없다 |

### I-14 QR 화면을 열기 전에 온 영수증
- **현상:** 2026-11-10 에뮬레이터 QA로 QR 화면은 "열 때 이미 있던 영수증은 기억만 하고 열지 않게" 바뀌었다(예전 영수증이 남아 엉뚱한 입력 창이 열렸다). 그 영수증을 여는 다른 화면이 없다.
- **영향:** 계산대에서 폰으로 먼저 올리고 차에서 [주유 기록 추가]를 누르면 QR만 보인다. 영수증은 `receipt_inbox`에 쌓인다.
- **정할 것:** Home·운행 기록에 "확정 안 한 영수증 N건" 진입을 둘지, QR 화면에 "먼저 올린 영수증" 목록을 둘지, 서버가 오래된 영수증을 만료시킬지.

## 2. 서로 다르게 동작하는 것

### I-11 알림과 앱의 [기록 종료]·문구 (앱 A 알림 ↔ 프론트)
| | 앱 A 시스템 알림 | 프론트 앱 |
|---|---|---|
| 종료 대기 제목 | "기록을 마칠까요?" + 카운트다운 | 질문 없이 운행 결과 카드 + "3초 후 자동 저장돼요." |
| 이어 가기 버튼 | [계속 기록] | [기록 이어가기] |
| [기록 종료] | 기다리지 않고 바로(`finalize`) | 주차 중 5초 대기(`requestStop`), 정차·주행 중 바로(`finalize`) — D-34. 끝나면 결과 카드가 단계와 무관하게 뜬다(정차·주행 중엔 버튼 없이 5초 뒤 저장, D-35) |
- **영향:** 같은 이름의 버튼이 서로 다르게 동작한다.
- **정할 것:** 알림 문구를 앱에 맞출지(앱 A `TripNotificationSpec`). 알림은 대개 운전 중·앱 밖에서 보므로 [기록 종료]가 바로 끝내는 지금 동작은 D-34(정차·주행 중엔 바로)와 맞다.

### I-13 검토 필요 건수 (G-03)
- **현상:** 화면(운행기록부 내보내기 요약)은 목적·운전자·거리 미확정만 센다. 엑셀·메일은 앱 A `ReviewCalculator` 7종(+ 배차 불일치·증빙 없음·중복 영수증·연료 이상치).
- **정할 것:** ① 만든 뒤엔 `ReportFile.reviewCount`로 바꿔 보이기 ② 미리보기 계약 요청 ③ 이름을 "미확정 N건"으로 바꿔 다른 숫자임을 드러내기.

### I-15 `originLabel` 주석과 실제 값
- **현상:** 계약 주석(`LiveTrip.originLabel`)은 "등록 장소 이름, 없으면 동 단위 주소"(R-9)인데, 실제(`6add996`)는 **내비 현재 위치 주소 문자열 전체**를 넣는다. 등록 장소 매칭은 없다.
- **영향:** Home·운행 기록·엑셀 출발지에 긴 주소가 보인다(한 줄 말줄임). I-05와 같이 정한다.

## 3. 연결됐지만 정책 논의가 필요한 것

### I-05 출발지·도착지 주소 표기 (2026-11-11 사용자 요청 — 논의 필요)
- **원하는 것:** 실제 운행기록부처럼 `광역 기초 읍면동 도로명 건물번호`.
  예: `서울 종로구 ○○동 ○○로 123-1` · `경기 용인시 수지구 포은대로 1-1` · `전남광주 북구 ○○로 10-1`.
- **Pleos 내비가 주는 것**(NaviHelper 3.0.5 / navi-data 3.0.4 클래스 직접 확인): 현재 위치·목적지·도착·최근 목적지·즐겨찾기·경유지 모두 **`address: String` 한 덩어리**와 `name`, 좌표, POI id. 시도·시군구·동·도로명·건물번호를 나눈 필드, 도로명/지번 구분, 좌표 → 주소 변환 API는 **없다**. 실제 문자열 형식은 실행해 봐야 안다(SDK 문서·`sdk-findings.md`에 예시 없음).
- **지금 저장되는 것:**
  - 출발지: 내비 현재 위치 `address` 그대로(`TripEntity.originLabel`). 내비 응답이 없으면 좌표만.
  - 도착지: 내비 목적지 **`name`만**(`withDestination`이 `address`를 버린다). 그래서 운행 기록·엑셀에 도착지 주소가 없다.
  - 엑셀: `출발지 → 도착지`를 이름으로 한 칸에(`ReportBuilder.route`).
- **읍면동:** 정식 도로명주소는 `시도 시군구 (읍·면) 도로명 건물번호 (동, 건물명)` — 동은 참고항목이라 내비 문자열에 없을 수 있다.
- **선택지:**
  | | 방법 | 얻는 것 | 대가 |
  |---|---|---|---|
  | A | 프론트 표기 규칙(`AddressFormat`) — 광역 이름 줄임(서울특별시 → 서울, 경기도 → 경기, "…통합특별시" → 앞부분) | 출발지 짧게 | 동은 문자열에 있을 때만, 도착지 주소는 여전히 없음 |
  | B | 앱 A: 도착지 `address` 저장 + 계약(`LiveTrip`·`TripRow`)에 출발·도착 주소, 엑셀 주소 칸 | 도착지도 같은 양식, 엑셀 주소 | 계약 변경(`contract/` 브랜치, A·B 승인) |
  | C | relay가 좌표로 역지오코딩(행안부 도로명주소·카카오 등) | 시도~건물번호 정확, 동 포함 | 외부 API 키·인터넷·서버 변경, 실험은 로컬 원칙(외부 호출 허락 필요) |
- **같이 정할 것:** 화면에서 장소 이름("본사", "판교 테크노밸리 거래처")과 주소 중 무엇을 보일지(주소만 / 이름 + 주소 한 줄 / 등록 장소면 이름). 첫 단계로 에뮬레이터에서 실제 `address` 문자열 몇 개를 받아 본다(`adb logcat -s AutoLog/navi`).

### I-06 운전자가 다음 운행에 그대로 붙는다
- **현상:** 앱 A는 고른 운전자를 차 상태(`vehicle_state.currentDriverUserId`)에 저장해 앱·차를 다시 켜도 유지한다. 초기화하는 곳이 없다. 기록은 앱을 열지 않아도 자동으로 시작된다(F-02).
- **영향:** 공용차에서 다음 사람이 앱을 열지 않고 출발하면 **앞사람 이름으로** 기록된다. 운전자 배지는 주차한 대기 Home에만 있어 운전 중에는 알 수 없다(D-30·D-31). 반대로 프론트는 앱을 새로 열 때마다 운전자 선택 화면을 보여 준다.
- **정할 것:** 시동 OFF·장시간 주차 뒤 운전자 비우기 / 운행 결과 카드에 "운전자: ○○ [변경]" / 앱을 열 때 저장된 운전자가 있으면 선택 화면 생략.

### I-07 잘못 붙은 운전자 바꾸기
- **현상:** 계약 `TripSessionApi.assignDriver(tripId, userId, source)`는 **어떤 운행이든** 바꿀 수 있다. 프론트 화면은 운행 기록의 "운전자 미확정" 줄에만 후보를 보인다.
- **정할 것:** 운행 결과 카드(사후 확인)에 운전자 칸을 둘지. 백엔드 변경 없이 프론트만으로 가능.

### I-08 기본값 "일반 업무" 자동 저장
- **현상:** 운행 결과 카드는 5초 뒤(또는 종료 대기 마감에) 지금 선택으로 저장한다. 처음 선택은 저장된 분류, 없으면 `DefaultPurposePolicy` = 일반 업무(D-27).
- **영향:** 사람이 보지 않고 내리면 출퇴근·개인 용무도 업무로 확정된다. 사람이 고른 것과 자동 저장한 것이 화면·엑셀에서 구분되지 않는다(`InputMode.TAP`로 같이 저장).
- **정할 것:** 자동 저장 표시(예: 입력 방식 `AUTO`)와 운행 기록의 "확인 필요" 모음, 또는 기본값을 미확정으로.

### I-09 운행이 짧은 정차마다 나뉜다 (사각지대 B-1)
- **현상:** 기어 P → 5초 뒤 종료(`T_GEAR_P_SEC`). 기어 D로 멈춤 10초 → 종료 대기 180초(`T_STOP_SEC`), 즉 멈춘 뒤 약 3분 10초에 종료(종료 시각은 멈춘 순간). 다시 움직이면 새 운행이 자동 시작.
- **영향:** 편의점·거래처 앞 잠깐 주차, 3분 넘는 정체·차단기·드라이브스루에서 운행이 둘로 나뉘고 결과 카드가 따로 뜬다.
- **정할 것:** 대기 시간 조정, 같은 날 짧은 간격의 운행 합치기(운행기록부 단계), 그대로.

### I-10 0 km 운행 (G-09 — 앱 A 정책 따름, 기록만)
- **규칙:** 자동 종료는 1분 미만 **그리고** 0.3 km 미만이면 버림(`DistancePolicy.NoMovement`). [기록 종료](`USER_REQUEST`)로 끝낸 운행은 0 km여도 0.0 km로 남김(`078c199`). 1분 넘게 서 있다 자동 종료된 0.0 km도 남는다.
- **영향:** 버려질 때 안내가 없다(결과 카드 없이 Home 대기로). 남은 0 km 운행은 지울 수 없다(I-04).
- **결정:** 2026-11-11 사용자 — 앱 A 정책을 그대로 따른다(R-12 철회). 버릴 때 안내 한 줄은 별도 논의 가능.

## 5. 데모 빌드와 실제가 다른 곳 (I-17, 기록만)
- 데모 가짜(`data/fake/FakeTripSession`)는 이동 없음 버림(1분 미만·0.3 km 미만)을 흉내 내지 않는다 — 데모에선 늘 결과 카드가 뜬다.
- 데모에는 알약·알약 권한 카드가 없다(`RecordingOverlay.None`). 차속 판단도 없다(데모 패널의 주행·정차·주차 버튼).
- 데모 연결 코드는 서버와 같은 규칙으로 검사만 한다(실제 서버 호출 없음).
