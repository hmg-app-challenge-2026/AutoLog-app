# 디자인 게이트 (2026-11-11)

차량 앱 화면 전체(기반 계획 + 나머지 화면 계획 Task 1~9)의 마지막 점검. 사용자 승인·맥 에뮬레이터 확인 전에 아래를 본다.
스크린샷 위치: `vehicle-app/src/test/screenshots/<크기>/<화면>_<dark|light>.png` (Linux 렌더링, 커밋하지 않음 — CONVENTIONS 4장).

## 기준 화면 — 실제 Pleos 화면 두 크기 (2026-11-10 사용자 지시)

- **`wide/` — 넓은 화면**: 앱 하나가 앱 영역 전체. 사용자가 공식 문서 그대로 설치한 Pleos Connect v2.1.0 에뮬레이터(API 34)의 앱 영역
  **2560×1268 dp**(디스플레이 2560×1440 px · 160 dpi에서 상태 표시줄 76 px · 하단 바 96 px를 뺀 것, V-01). 실제 에뮬레이터 캡처
  (`docs/screenshots/font-size/pleos-*.png`)와 나란히 놓고 배치·글자 크기가 일치함을 확인했다.
- **`narrow/` — 좁은 화면**: 앱 둘의 1:1 분할 한 칸 **1280×1268 dp**. Pleos Window Policy(document.pleos.ai `docs-design/getting-started/window`)
  "앱 2개 실행 시 1:1(기본값)"을 앱 영역 폭에 적용한 값 — 창 사이 경계 몇 dp는 아직 재지 않았다(V-01). 레이아웃 판정은 NARROW.
- 둘 다 밀도 1.0으로 찍어 픽셀이 에뮬레이터와 같다. 예전 1024×640 · 504×640 · 720×1100(근거 없는 잠정 비율)은 지웠다.
- **좁은 화면도 넓은 화면과 같은 글자·크기**(디자인 언어 1.33): 예전 504 dp 폭에 맞춘 축소(타일 두 줄 이름·작은 제목·`dense` 버튼·128 dp 운전자 타일)는 1280 dp에선 필요 없어 걷어냈다. 두 칸 배치(운행 결과·주유·설정·운행 기록 툴바·내보내기 요약)도 그대로 쓴다. 한 칸만 쓰는 화면은 세로로 긴 창(TALL)뿐.
- Window Policy의 "2:1 또는 1:2(기본값 2:1)" 분할(어느 디스플레이 기준인지 문서 글자로는 불분명)과 12.9″ 세로 프리셋은 FormFactorConsole로 재면 크기를 더한다.

## 최종 점검 결과 (2026-11-10, Task 9)

디자인 언어 13장 체크리스트로 넓은 화면(2560×1268) 전체와 당시의 잠정 크기를 훑어 고친 것:

| 화면 | 문제 | 고친 것 |
|---|---|---|
| 운행 기록 조회 · 운행기록부 · 설정(좁은 창 상세) · 주유 QR | 가운데 960 dp(QR 버튼 640 dp)로 모으려던 내용이 **2560 dp 전체로 퍼짐** — `fillMaxWidth().widthIn(max)` 순서 버그(1024 폭에서는 차이가 작아 몰랐다). 줄 글자는 왼쪽 끝, ›는 오른쪽 끝 | `widthIn(max).fillMaxWidth()`로. 가운데 960 dp 폭 |
| 주유 직접 입력 | 칸은 가운데 960 dp인데 [추가하기]만 화면 끝까지 | 한 칸 배치면 버튼도 칸과 같은 폭(영수증 두 칸 배치는 전폭 그대로) |
| Peek | 2560 화면 가운데 560 dp 칸에서 목적지·상황 줄이 어절 중간에 꺾임("물어볼/게요") · 1024×640·504×640에서 맨 아래 상황 줄이 반쯤 잘림 · 상태 줄이 배지보다 위 | `peekMaxWidth` 560 → 960 dp, 넘치면 상황 줄을 통째로 생략(`FitOrDrop`, 스펙 7.0 생략 규칙), 상태 줄을 `TopLine`에(배지와 같은 높이) |
| Home 좁은 창(기록 중) | 상태 줄이 배지에 밀려 "35분 / 경과" 두 줄 | 좁은 창은 "35분", `StatusLine`은 늘 한 줄(넘치면 보조 말줄임) |
| 설정 연결 코드 팝업 | 라벨 · 코드 칸 · 숫자판이 붙어 있음(`ModalCard` 내용엔 간격이 없다) | 팝업 내용 16 dp 간격 묶음 |

남은 것(이번에 고치지 않음):
- 한국어 어절 줄바꿈(`WordBreak.Phrase`)은 Robolectric 렌더링에 적용되지 않는다 — 실기기·에뮬레이터에서 확인(V-, 아래 7번).
- 설정 메일 칸은 넓은 창 오른쪽 상세 폭(약 1,430 dp)을 그대로 쓴다 — 읽는 데 문제는 없어 그대로.

## 맥 에뮬레이터에서 (스펙 10.3)

1. `./gradlew :vehicle-app:installDemoDebug` → 앱 실행 → 운전자 선택 → Home
2. 오른쪽 위를 길게 누르기 → 데모 패널 → [주행 시나리오 재생] → 앱이 물러남(V-12) → 기어 P면 운행 결과 카드(5초 막대, D-28)
3. 데모 패널 [정차(신호 대기)] → Peek, 누를 것 없음, 상태 줄과 배지 높이
4. 하단 타일 [주유 기록 추가] → (데모 영수증이 있으면) 입력 창 바로 · [운행 기록 조회] → 줄 탭 → 사후 확인 카드 · [운행기록부 내보내기] 2탭 · [설정] 8개 섹션
5. 윈도 바로 portrait ↔ landscape, 다른 앱과 1:1 분할 → 잘림·겹침 없음, 상태 유지
6. 차량 설정에서 주간·야간 전환 → 깜빡임 없음(V-08)
7. 한국어 어절 줄바꿈이 실기기에서 적용되는지("앱이 꺼진 동안 15.0 km를 달렸어요" 팝업, 운행 결과 분류 문구)
8. FormFactorConsole 프리셋별 dp·DPI·px와 **분할 화면 한 칸의 dp**를 기록(V-01) → `docs/verification.md`, `Screenshots.kt`의 NARROW·TALL 크기 갱신
9. vehicle flavor 설치 후 VHAL로 기어 D·속도 주입 → `adb logcat -s AutoLog/ui`로 CarUxRestrictions 값(V-04, V-11), 키보드 규제 시 설정 입력 칸만 막히는지

## 구현 중 계획과 달라진 점 (다른 사람이 이어받을 때 참고)

| 계획 | 실제 | 이유 |
|---|---|---|

## 결정이 필요한 것

- 토큰 값 조정(색·크기)이 있으면 `docs/design-language.md`를 먼저 고치고 `ContrastTest`를 통과시킨다.
- V-01 측정값으로 `WindowLayout.kt` 임계값과 `Screenshots.kt` 크기를 바꾼다.
- NARROW에서 ProfilePicker의 [나중에 선택]이 스크롤해야 보인다(미확정 운행 질문이 있을 때). 그대로 둘지 결정.
