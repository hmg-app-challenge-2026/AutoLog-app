# AutoLog 기능 명세서

| 항목 | 내용 |
|---|---|
| 문서 목적 | AutoLog MVP(공모전 시연 범위)의 기능을 ID 단위로 정의하고, 입력·출력·예외·수용 기준을 확정해 개발·테스트·시연의 공통 기준으로 삼는다 |
| 관련 문서 | AutoLog_기획서.md(왜·무엇), AutoLog_기술명세.md(어떻게) |
| 아키텍처 원칙 | **운행 기록의 원본은 차량 Room이다. 서버는 폰·관리자가 차에 넣어주는 것(영수증 OCR·직원·거래처·배차·수신자)만 중계하는 우체통이다.** 엑셀·메일은 차가 직접 만든다 |
| 범위 | 차량 앱(Pleos Connect) · 중계 서버 · 운영 웹(경량) · 폰 카메라 페이지. 12.03–04 시연 기준 |
| 우선순위 | **P0** 시연 필수 · **P1** 11.30까지 · **P2** 공모전 이후 |
| 버전 | v0.3 (2026-11-07) — 중계 서버 노선 확정 |

## 1. 용어

| 용어 | 정의 |
|---|---|
| Trip(운행) | 운행 시작 Odometer 스냅샷부터 종료 스냅샷까지의 연속 이동 1건. **차 Room에만 존재** |
| Stop(정차) | Trip 도중 자동 종료 대기(기어 P 5초 / 그 외 180초) 안에 다시 출발한 정차 |
| Odometer | Vehicle SDK가 제공하는 차량 계기판 누적 주행거리(km) |
| Fix | Fused Location SDK 좌표 1건 |
| Place(등록 장소) | 본사·지점·거래처·주유소·자택. 서버가 배포하거나 차 안에서 등록. 반경 150 m |
| Schedule(배차) | 차량 사용 계획(일시·차량·운전자·목적지·목적). 운영 웹에서 등록 → 차로 배포 |
| Inbox(우체통) | 서버가 차량별로 보관하는 "아직 차가 가져가지 않은 편지". 종류: RECEIPT / USERS / PLACES / SCHEDULES / RECIPIENTS |
| 검토 | 사람 확인이 필요한 운행·비용 표시. **차가 계산**해 엑셀 "검토" 열로 출력 |
| 주차·정차 상태 | 주차 = Gear=PARK(기어 신호가 없으면 주차 브레이크·시동 → 거리 불변 60초). 정차 = P가 아니고 Odometer 변화 없음 ≥ 10초. 판정 불가 시 주행 중 |
| 놓친 운행 | 앱이 기록하지 않았지만 계기판 차이로 존재가 확인되는 운행 |

## 2. 사용자와 역할

| 역할 | 접점 | 할 수 있는 것 |
|---|---|---|
| DRIVER(운전자) | 차량 앱, 폰 카메라 페이지(QR) | 사용자 선택, 운행 시작·종료, 목적 승인, 주유 음성 입력, 영수증 촬영(폰), OCR 결과 확인(차), 거래처 등록, 엑셀 메일 발송 |
| MANAGER(관리자) | 운영 웹 | 차량·연결 코드, 직원, 장소, 배차, 엑셀 수신자 등록 → 차량에 배포 |
| ACCOUNTANT(회계) | 메일 | 차량별 운행기록부 엑셀 수신, "검토" 열 확인 → 운전자에게 요청 |
| SYSTEM | — | 자동 기록, 추천, 검토 계산, OCR 중계, 배포 |

## 4. 차량 앱

### F-01 차량 연결 및 기기 등록 (P0)

| 항목 | 내용 |
|---|---|
| 설명 | Pleos Vehicle Service 연결 + 헤드유닛을 조직 차량 1대로 서버에 등록 |
| 사전조건 | 회사가 운영 웹에 가입(가입한 사람이 관리자)하고 차량 등록 후 **연결 코드**(6자리, 24h) 발급 (F-50) |
| 흐름 | ① `Vehicle.initialize()`, `NaviHelper.initialize()`, `FusedLocation.initialize()` ② Odometer capability → 현재 누적거리 표시 ③ CarInfo 모델·VIN 시도 ④ 연결 코드 6자리만 입력(서버 주소는 빌드에 고정 — `BuildConfig.RELAY_BASE_URL`, 2026-11-13) → `POST /devices` → 기기 토큰(암호화 저장) ⑤ 즉시 F-11 인박스 1회 수신(직원·장소·배차·수신자·회사 메일 계정·목적·목적 규칙) |
| 예외 | Vehicle Service 실패 → 재시도(5초×12) · Odometer 불가 → "지원되지 않는 차량", 수동 입력 가능 · 코드 무효 → 재입력 · **서버 불가** → 등록은 보류하고 로컬 기능은 전부 동작(직원은 설정에서 직접 입력) |
| 수용 기준 | 10초 내 Odometer 표시. 코드 입력 후 서버 `devices`에 행. 재실행 시 코드 없이 연결. 서버를 꺼도 운행 기록이 된다 |

### F-02 운행 시작 (P0)

| 항목 | 내용 |

### F-16 백그라운드 기록 — Foreground Service (P0)

| 수용 기준 | 운행 시작 → 내비로 전환 → Odometer 변경 → 알림 km 갱신. 10분 생존 |

### F-04 정차 감지·운행 종료 (P0)

| 항목 | 내용 |
|---|---|
| 신호(OR) | Gear=PARK(**즉시 Odometer 재조회·저장**) · RouteState=도착 · Odometer 불변 10초 · 시동 OFF · 종료 탭/알림 확인 |
| 흐름 | STOP_CANDIDATE(이유·`deadlineAt`) → 대기: 기어 P **5초**(헤즈업 알림 "기록을 마칠까요?" + 카운트다운 [계속 기록][기록 종료]) / 움직임 없음·내비 도착 **180초** / 시동 OFF 대기 없음 → 재출발·[계속 기록] 시 Stop 저장·복귀 / 만료·[기록 종료] → FINALIZING |
| 수용 기준 | 종료 탭 3초 내 ReviewTrip. 기어 P 후 5초 안에 [계속 기록]이면 Trip 유지, 아니면 자동 ReviewTrip. 기어 신호 없이 60초 정차 후 재출발 시 Trip 유지, 180초 후 자동 ReviewTrip |

### F-05 운행거리 계산 (P0)

| 항목 | 내용 |
|---|---|
| 규칙 | `end − start`, 소수 1자리. `end ≥ start`, ≤ 1,500 km, (≥ 60초 OR ≥ 0.3 km) |
| 실패 | 조회 실패 → `null`, `UNAVAILABLE`, NEEDS_RECOVERY. **추정 금지** |
| 보존 | 원본 start/end·시각·SDK 버전을 `rawSnapshotJson`. 수정은 `USER_EDITED` 별도 |
| 수정 | 운행 결과 카드 수정 모드 [거리 수정하기] → `editedDistanceKm`(0 초과 1,500 km 이하). 원본 `distanceKm`은 덮지 않고, 목록·엑셀은 수정값 + 엑셀 비고 "거리 수정(계기판 n km)". 거리 미확정 운행도 여기서 채운다(2026-11-13) |
| 수용 기준 | 23.4 km. 콜백 끊으면 NEEDS_RECOVERY·거리 공란 |

### F-06 목적지 연결 (P0)

| 항목 | 내용 |
|---|---|
| 흐름 | `getDestinationInfo()` + 콜백 → 라벨·좌표, 변경 이력 |
| 미설정 | ReviewTrip에서 Fix→Place 매칭 → 최근 목적지 3 → 등록 장소 → 직접 입력 |
| 도착 판정 | 운행이 끝난 직후 실제 위치(내비 현재 위치 → 위치 SDK)가 내비 목적지 300 m 안이면 목적지 이름, 아니면 실제 위치의 등록 장소·건물 이름(2026-11-13) |
| 결과 화면과 같게 | 차가 멈춰 종료 대기([기록 이어가기])에 들어가는 순간 위 판정으로 도착지를 정해 결과 화면에 보이고, 운행이 확정되면 **그 도착지를 그대로 저장**한다. 기록을 이어가면 내비 목적지로 돌아간다(2026-11-14) |
| 수용 기준 | 설정 3초 내 표시. 변경 시 최종값 + 이력 2건 |

### F-42 인박스 조회·확인 (P0)

| 항목 | 내용 |
|---|---|
| API | `GET /inbox`(기기 토큰) → `[{id, kind, payload, created_at}]` · `POST /inbox/{id}/ack` → 삭제 |
| 보관 | ack 없으면 30일 후 삭제. 썸네일 URL은 서명 URL 7일, 차가 inbox를 가져갈 때마다 새로 서명 |
| 수용 기준 | ack 후 재조회 시 없음. 다른 차 토큰으로 조회 불가 |

### F-43 기준 정보 배포 (P1)

| 항목 | 내용 |
|---|---|
| 동작 | 운영 웹에서 직원·장소·배차·수신자·메일 계정·목적·목적 규칙 변경 시 → 조직 모든 차량 inbox에 **전체 목록(최신 값)**으로 적재(kind=USERS·PLACES·SCHEDULES·RECIPIENTS·MAIL_ACCOUNT·PURPOSES). 배차는 해당 차량만. MAIL_ACCOUNT는 inbox 표에 비밀번호 없이 넣고 차가 가져갈 때 채운다 |
| 수용 기준 | 차량 3대 조직에서 직원 추가 → inbox 3건. 차가 ack 전 두 번 바뀌면 최신 1건만 |
