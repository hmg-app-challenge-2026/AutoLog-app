# 화면 전환·조작 모션 구현 계획

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 버튼을 누르거나 화면·상태가 바뀔 때 "툭 바뀌는" 곳을 없애고, 토스·iOS처럼 부드럽고 자연스러운 모션으로 어디서 왔고 어디로 가는지 설명한다.

**Architecture:** 모든 움직임은 스프링(넘침 없는 `spring.smooth`·`spring.quick`, 작은 "톡"만 `spring.bouncy`). 모션 값은 전부 `MotionTokens`(디자인 언어 8장) 한 곳에 둔다. 화면 전환은 백스택 변화로 방향(앞으로·뒤로·띄우기·같은 자리)을 고르는 순수 함수 하나가 정하고, `FullApp`의 `AnimatedContent`가 그 결과로 그린다. 팝업은 사라질 때까지 내용을 붙잡는 `ModalHost`로 감싸 들어올 때와 나갈 때 모두 움직인다. 화면 안의 작은 변화(선택·강조·내용 교체·펼침)는 공용 도우미(`FadeThrough`, `DirectionalContent`, `animateSelectColor`)로만 만든다.

**Tech Stack:** Jetpack Compose animation(`spring`, `AnimatedContent`, `AnimatedVisibility`, `animate*AsState`, `Animatable`, `animateContentSize`, `Modifier.animateItem`), Roborazzi(프레임 캡처), Robolectric `mainClock`.

**Spec:** `docs/superpowers/specs/2026-11-09-autolog-frontend-design.md`(1.1 사용 3단계, D-11 Peek 정적, 6.9 잠금) · `docs/design-language.md` 8장 모션.

## Global Constraints

- **Pleos 가이드**(2026-11-10 확인, document.pleos.ai `foundations/animation` · `Introduction/intro` · `driver-distraction-guideline`): 애니메이션은 **상태 설명용**. 장식·반복 금지. 주행 중 자동 애니메이션·잦은 화면 전환 최소화. **입력 후 시스템 반응 0.25초 이내**(늦으면 "처리 중" 표시). 전환 시간·곡선 수치는 가이드에 없다.
- 사용 3단계 그대로: **주행 = 화면 없음 · 정차(Peek) = 움직임 없음(D-11, 경로 화살표만 예외) · 주차(FULL) = 이 계획의 모션 전부.** `tier != FULL`이면 `MotionTokens.Static`.
- 시스템 "애니메이션 줄이기"(`ANIMATOR_DURATION_SCALE == 0`)면 지금처럼 `MotionTokens.Still` — 모든 모션 즉시.
- 모션 값은 토큰만. 화면 코드에 `tween(300)`, `spring(...)`, 리터럴 dp 이동 거리를 쓰지 않는다(CONVENTIONS 3장).
- 움직이는 것은 `graphicsLayer`(이동·배율·투명도)로. 큰 면의 크기·레이아웃을 매 프레임 바꾸지 않는다. 그림자·블러 애니메이션 없음(2560×1268 화면, 차량 GPU).
- **입력을 막지 않는다**: 새 화면은 전환 첫 프레임부터 누를 수 있다(0.25초 규칙). 나가는 화면은 누를 수 없다.
- 기존 스크린샷(`wide/`·`narrow/`)은 `ambientMotion = false` → `Still`이라 바뀌지 않아야 한다(바뀌면 버그).

## 0. 진단 — 지금 왜 "바로 바뀐다"고 느끼나

코드 조사(2026-11-10, `grep AnimatedContent|AnimatedVisibility|Crossfade|animate*AsState|Animatable`) 결과 모션이 있는 곳은 7곳뿐이다.

| 있는 것 | 상태 |
|---|---|
| 화면 전환(`FullApp`) | 들어오는 화면: 투명도 220 ms + 0.98→1 + **폭의 4%** 슬라이드. 나가는 화면: 150 ms 페이드. **앞으로·뒤로가 같은 방향**이고, 2560 dp에서 4%(≈100 dp)라 거의 안 보인다 |
| 팝업 등장(`ModalCard`) | 0.94→1 + 투명도. **닫힐 때는 즉시 사라진다**(조건부 컴포지션에서 빠짐) |
| 누름(`tappable`) | 0.97배 90 ms → 스프링 복귀 |
| 운전자 아바타 hero | 운전자 선택 → Home 배지 |
| 운행 결과 → 저장 완료 | `Crossfade` |
| 체크(`SuccessCheck`), 남은 시간 막대, 숫자 교체(`HeroMetric`), 경로 화살표 | 있음 |

**없는 것(= 툭 바뀌는 곳):** 팝업 닫힘 · Home 대기↔기록 중 · 하단 타일 강조 · 선택 행(라디오·체크) · 버튼 개수·이름 변화 · 달 이동 · 설정 상세 전환 · 내보내기 단계 · 운전자 지정 줄 접힘 · 정차↔주차 전환 · 목록 추가·삭제.

**확인해야 할 가설(T0):** Pleos 에뮬레이터의 시스템 애니메이션 배율이 0이면 앱이 `Still` 세트를 써서 **있는 모션까지 전부 멈춘다**(`Theme.kt systemAnimationsOff`). 맥에서 `adb shell settings get global animator_duration_scale`(+ `window_animation_scale`, `transition_animation_scale`)로 확인한다.

## 1. 원칙 — 토스·iOS에서 가져올 것

1. **공간이 하나다.** 들어가면 오른쪽에서 오고 나오면 왼쪽으로 돌아간다. 결과·완료처럼 "위에 얹히는" 것은 아래에서 떠오르고 내려가며 사라진다. 같은 자리에서 내용만 바뀌면 그 자리에서 교차한다. 방향이 곧 의미다.
2. **모든 움직임은 스프링(iOS·Apple 방식, 2026-11-10 사용자 결정).** 멈춘 상태에서 출발하는 스프링은 속도 0에서 가속해 정점을 찍고 길게 감속한다 — "느리게 출발 → 빠르게 → 천천히 끝"이 물리로 들어 있다. 전환 도중 뒤로를 눌러도 지금 속도를 이어받아 자연스럽게 되돌아간다(tween은 처음부터 다시 시작해 덜컥). 화면 전환·팝업·내용 교체는 **넘침 없는** 스프링(감쇠 1), 손에 반응하는 작은 "톡"(라디오 점·체크·완료 표시)만 살짝 튀는 스프링. 예외: 남은 시간 막대는 흐르는 시간을 보여 주므로 직선. (검토했던 안: S자 cubic(0.42, 0, 0.2, 1) tween — 느린 출발이 더 눈에 띄지만 도중에 끊길 때 덜컥하고 시간이 고정이라 iOS 느낌과 멀어 기각)
3. **빠르게, 사라짐은 더 빠르게.** 입력 → 첫 프레임 즉시. 화면 전환 ≈ 350 ms, 작은 변화 150–250 ms. 사라지는 쪽은 나타나는 쪽의 약 60%.
4. **움직임은 원인 가까이에서.** 누른 버튼이 바뀌면 그 버튼이 바뀐다(다른 곳이 깜빡이지 않는다). 숫자가 바뀌면 숫자만.
5. **차 안이라 덜 한다.** 장식용 등장 연출(목록 줄줄이 떠오르기, 반짝임, 패럴랙스 배경)은 하지 않는다. 기본값은 "상태를 설명하는 움직임"만.

## 2. 모션 토큰 (디자인 언어 8.2를 이 표로 바꾼다)

| 토큰 | 값 | 쓰임 |
|---|---|---|
| `spring.smooth` | `spring(dampingRatio = 1f, stiffness = 320f)` — 응답 ≈ 0.35 s, 넘침 없음(SwiftUI `.smooth`) | 화면 이동·띄우기·내용 교체·펼침·달 이동 |
| `spring.quick` | `spring(1f, 700f)` — 응답 ≈ 0.24 s, 넘침 없음 | 사라짐·닫힘·투명도·색 |
| `spring.bouncy` | `spring(0.55f, 600f)` — 살짝 튐 | 라디오 점·체크·완료 표시의 "톡"(손에 반응하는 작은 것만) |
| `nav.push` | 들어오는 화면: 오른쪽 **전체 폭**에서 0으로(`spring.smooth`). 나가는 화면: 0 → 왼쪽 **폭의 30%** + 덮개(`scrim`) 0 → 0.35(`spring.smooth`) | 화면 깊이 들어가기(iOS 패럴랙스) |
| `nav.pop` | `nav.push`의 반대(`spring.smooth`). 떠나는 화면이 위(zIndex)에서 오른쪽으로 빠진다 | 뒤로 |
| `nav.present` | 들어옴: 아래 `Space.s9`(96 dp)에서 위로 + 0.96→1(`spring.smooth`) + 투명도(`spring.quick`). 뒤 화면은 그대로 | 운행 결과 카드(운행 직후) |
| `nav.dismiss` | 나감: 아래로 48 dp + 투명도 1→0(`spring.quick`) | 운행 결과 닫힘 |
| `nav.fadeThrough` | 나가는 쪽 투명도(`spring.quick`), 들어오는 쪽 투명도 + 0.98→1(`spring.smooth`, 나가는 쪽이 거의 사라진 뒤 보이도록 들어오는 쪽 투명도에 짧은 지연 90 ms) | 같은 자리 화면 교체(`replaceTop`: QR → 입력 창), 처음으로 돌아가기(`replaceAll`) |
| `modal.enter` | scrim 투명도(`spring.quick`). 카드 0.92→1 + 투명도(`spring.smooth`) | 팝업 열림 |
| `modal.exit` | 카드 1→0.96 + 투명도 → 0, scrim(`spring.quick`) | 팝업 닫힘 |
| `content.swap` | `nav.fadeThrough`와 같음, 들어오는 쪽만 8 dp 위로 | 화면 안 내용 교체(Home 상태, 설정 상세, 결과 문구) |
| `content.directional` | 방향 쪽으로 48 dp 슬라이드(`spring.smooth`) + 페이드(`spring.quick`) | 달 이동(‹ ›) |
| `content.expand` | 크기(`spring.smooth`) + 투명도(`spring.quick`) | 줄 펼침·접힘, 버튼 개수 변화, 안내 줄 생김·사라짐 |
| `select` | 색·테두리(`spring.quick`). 라디오 점·체크 표시 0→1(`spring.bouncy`) | 선택 행, 강조 타일, NavRow 선택, 버튼 활성·비활성 |
| `press` | 지금 그대로(0.97배 90 ms → `snappy`) + 면 한 단계 밝게(디자인 언어 8.3 ①에 있는데 구현 안 됨) | 누를 수 있는 모든 것 |
| `tier.fade` | 투명도(`spring.quick`) | 정차·주차 전환 |

- 이동 거리는 `Size`/`Space` 토큰(`Space.s9`, 48 dp = `Space.s7`, 8 dp = `Space.s2`). 폭 비율(100%·30%)은 `MotionTokens` 상수.
- `Static`·`Still`이면 모든 스펙이 `snap()` — 지금 방식 그대로 토큰 함수 안에서 고른다.

## 4. 구조

```
ui/design/
  MotionTokens.kt            ← 2장 토큰 추가(기존 함수 이름은 유지, 쓰는 곳 없어지는 것은 삭제)
  motion/
    NavTransition.kt         ← enum NavTransition { PUSH, POP, PRESENT, DISMISS, FADE_THROUGH, NONE }
                               + fun navTransitionOf(from: List<Route>, to: List<Route>): NavTransition (순수 함수)
    RouteTransitions.kt      ← NavTransition → ContentTransform(EnterTransition togetherWith ExitTransition, zIndex)
    ContentMotion.kt         ← FadeThrough(target) { }, DirectionalContent(target, direction) { },
                               animateSelectColor(), Modifier.expandingContent()
  components/
    Overlay.kt               ← ModalCard 등장 코드를 걷어내고 ModalHost에 맡긴다
    ModalHost.kt             ← fun <T : Any> ModalHost(value: T?, content: @Composable (T) -> Unit)
                               : 사라지는 동안 마지막 값을 붙잡고 modal.enter / modal.exit
ui/root/
  FullApp.kt                 ← AnimatedContent(targetState = stack, contentKey = { it.last() }) + navTransitionOf
  AutoLogRoot.kt             ← AnimatedContent(tier) + tier.fade
nav/Route.kt                 ← Route.TripResult(mode = AFTER_TRIP)는 "띄우는 화면"(presented) 표시
```

- **방향 판정 규칙**(`navTransitionOf`): 새 맨 위가 띄우는 화면 → `PRESENT` · 떠난 맨 위가 띄우는 화면 → `DISMISS` · 스택이 길어짐 → `PUSH` · 짧아지고 새 맨 위가 이전 스택에 있었음 → `POP`(`replaceAll`로 처음 화면에 돌아가는 것도 — iOS popToRoot와 같음) · 길이 같음(`replaceTop`) 또는 처음 화면 바꾸기 → `FADE_THROUGH` · 맨 위가 같음 → `NONE`. 화면 코드는 방향을 모른다(Navigator 호출만 그대로).
- **pop은 떠나는 화면이 위**: `ContentTransform.targetContentZIndex`를 pop일 때 -1로.
- **입력**: 나가는 화면은 `AnimatedContent`가 입력을 막지 않으므로 나가는 쪽에 터치 삼키기 레이어를 둔다(두 번 누르기로 겹친 push 방지). 새 화면은 바로 누를 수 있다.
- **ViewModel 저장소**(`RouteViewModelStores.retainOnly`)는 지금처럼 전환이 끝난 뒤 다음 구성에서 지운다 — pop 애니메이션 동안 떠나는 화면 ViewModel이 살아 있어야 한다(지금 코드가 이미 그렇다, T2에서 테스트로 고정).
- **팝업 호출 11곳**은 `if (state != null) ModalCard {}` → `ModalHost(state) { ModalCard {} }`로 바꾼다. 닫힘 모션 동안 붙잡은 값으로 그리므로 화면 상태는 바로 null이 돼도 된다.
- 공용 도우미 밖에서 `AnimatedContent`·`animateColorAsState`를 직접 쓰지 않는다(CONVENTIONS에 한 줄 추가).
